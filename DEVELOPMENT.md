# Development

## Layout

| Path | What |
| --- | --- |
| `Unity/` | MeatKit project (Unity **5.6.7f1**, MeatKit **3.0.7**, see below). `Assets/MeatKit` is MeatKit's; ours is `Assets/OriginsStaffs`. |
| `Unity/Assets/OriginsStaffs/Ripped/` | Meshes and textures from BO2. Gitignored except `.meta` files; regenerate below. |
| `Unity/Assets/OriginsStaffs/Prefabs/`, `Data/` | Generated by **Origins Staffs > Build Staffs** (staffs, effects, item data, build profile) and **Rebuild Ripped Prefabs** (`Prefabs/Visual/`). Gitignored: they carry BO2-derived data and a local r2modman path. |
| `Unity/Assets/OriginsStaffs/Art/` | The spawner folder thumbnail. |
| `tools/` | Extraction scripts, the browser model viewer, and the OtherLoader `.unitypackage`. |
| `extracted/` | Curated rip from `collect_assets.py`. Gitignored. |

Game assets are never committed. Everything under `Ripped/` and `extracted/` is rebuilt from
your own Black Ops II install, and `Prefabs/` and `Data/` from those by the build menu.

## Extracting from Black Ops II

Tools live outside the repo, in `X:\Tools\OpenAssetTools` (OAT v0.34.0).

Origins' streamed textures are in `dlczm4.ipak`, but the zone asks for `zm_tomb.ipak`. Without
that file every texture fails with `Could not find data for image`. A hardlink under the
expected name fixes it without touching the game folder:

```powershell
New-Item -ItemType HardLink -Path X:\Tools\OpenAssetTools\ipak_alias\zm_tomb.ipak -Target "X:\SteamLibrary\steamapps\common\Call of Duty Black Ops II\zone\all\dlczm4.ipak"
```

Then, from `X:\Tools\OpenAssetTools`:

```bash
ZONE="X:/SteamLibrary/steamapps/common/Call of Duty Black Ops II/zone/all/zm_tomb.ff"
./Unlinker.exe --model-format GLTF -o "zone_dump/?zone?" "$ZONE"
./Unlinker.exe --search-path X:/Tools/OpenAssetTools/ipak_alias --include-assets image -o "zone_dump_img/?zone?" "$ZONE"
./Unlinker.exe --include-assets xmodel --model-format OBJ -o "zone_dump_obj/?zone?" "$ZONE"
```

Then, from the repo root (Pillow is in the OAT folder's venv):

```bash
X:/Tools/OpenAssetTools/.venv/Scripts/python tools/collect_assets.py X:/Tools/OpenAssetTools/zone_dump/zm_tomb X:/Tools/OpenAssetTools/zone_dump_img/zm_tomb extracted
python tools/export_unity.py X:/Tools/OpenAssetTools/zone_dump_obj/zm_tomb extracted Unity/Assets/OriginsStaffs/Ripped fire water bolt air
```

`export_unity.py` stages OBJ meshes (Unity 5.6 cannot read GLTF), PNG textures, and
`staff_assets.json`. That file holds what OBJ loses: the BO2 attachment tags (`tag_tip`,
`tag_crystal`, `tag_reload`, `tag_flash`) and which texture each material uses. Those feed the
visual-only prefabs.

The playable staffs come from `export_assembly.py` instead:

```bash
X:/Tools/OpenAssetTools/.venv/Scripts/python tools/export_assembly.py X:/Tools/OpenAssetTools/zone_dump/zm_tomb X:/Tools/OpenAssetTools/zone_dump_img/zm_tomb extracted Unity/Assets/OriginsStaffs/Ripped all
```

`all` exports every element (or name them: `fire ice lightning wind`). It writes
`Ripped/Assembly/Staff_<Element>[_Upgraded].json`. Each one holds BO2's first-person
staff, tip, crystal and reload assembly (attached as the weapon file does), the world model's
lower shaft and rubber handle joined onto it, the skeleton and skin weights, and the reload
animation's bone tracks. It also copies the effect textures, spawner icon (`Ripped/FX`) and
sounds with their BO2 volume and pitch (`Ripped/Sounds/<element>`). Everything is already in Unity's
left-handed, metre space, so Unity imports no model files for it.

`tools/assembly_viewer.html` renders those JSON files in the browser, with a slider that scrubs
the reload, so the export can be checked without Unity. `tools/read_xanim.py` decodes BO2's
compiled animations (`zone_dump/zm_tomb/xanim/`).

## Building the playable staffs

**Origins Staffs > Build Staffs** turns every `Ripped/Assembly/*.json` into
`Prefabs/Staff_*.prefab`, plus the fireball, impact and muzzle-flash prefabs (`Prefabs/FX`),
item data and spawner entries (`Data/`), and the OtherLoader/MeatKit build profile
(`Data/Build/`). **Origins Staffs > Build Staffs + Copy Mod To r2modman** then runs MeatKit's
build straight into the r2modman Default profile.

Runtime scripts (`Assets/OriginsStaffs/Scripts`, namespace `OriginsStaffs`, which the build
profile lists in Additional Namespaces so MeatKit ships it):

| Script | Role |
| --- | --- |
| `OriginsStaff` | The gun (`FVRFireArm`), held at the blue rings: trigger, release button, its own two-hand aim, charges, shots, recoil, crystal glow. |
| `StaffSupportGrip` | The black handle (`FVRInteractiveObject`): support hand, no trigger; grabbing it on a loose staff picks the staff up by the rings. |
| `StaffLever` | The reload mechanism under the rings; carries the trigger hand's pose and is pumped by closing and opening the gap between the hands. |
| `StaffImpactSound` | Impact sound from a 3D source that fades with distance (H3VR's explosion pool is map-wide). |
| `StaffReloadRig` | Poses the reload mechanism at any frame of BO2's reload animation. |
| `StaffProjectile` | Fire and lightning ball: straight flight, then a burst. Fire burns and ignites; lightning applies BO2's direct + radius damage per sosig and stuns survivors. |
| `StaffConeShot` | Ice and wind shot: BO2's scripted target search in a cone in front of the staff, carried out as its bolts arrive. |
| `StaffBolt` | The visible ice shard or ball of wind: BO2 speed and lifetime, collides with the level only. |
| `StaffFreeze` | BO2's ice_affect_zombie on one sosig: icicle in the chest, freeze, then shatter or damage and thaw. |
| `StaffDamage` | `StaffElement`, sosig searches, and BO2 damage in H3VR terms (see Elements). |
| `StaffChargedShot` | An upgraded staff's level 2 or 3 charged shot: launches the element's projectile. |
| `StaffFireGrenade`, `StaffFirePool`, `StaffBurn` | Fire charge: the lobbed grenade, the burning area it leaves, and a sosig left burning. |
| `StaffBlizzard` | Ice charge: the blizzard that freezes and shatters everything inside it. |
| `StaffLightningOrb` | Lightning charge: the drifting ball and its arcs. |
| `StaffWhirlwind` | Wind charge: the whirlwind that drags sosigs in. |
| `StaffSpin` | Turns a transform so local-space particles swirl (storm, tornado). |
| `StaffTimedEffect` | Fades and removes muzzle-flash and impact effects. |

Two-hand aim is computed in `OriginsStaff.GetRotTarget` (handle hand -> trigger hand), not by
H3VR's front-grip code, which needs the front hand ahead of the trigger hand and flips the gun
as the hands close in. It blends back to one-handed aim below 12 cm of hand separation.

The lever is a pump. Pulling it back follows the hand through BO2's tube snap (frames 12-16);
past 60% of its 8 cm stroke it springs to the stop and BO2's frames 16-45 play on their own at
BO2's speed (crystal out, petals open, crown turns, crystal spins). Pushing it forward past half the
stroke slams it home and plays frames 45-57 (crystal re-seats, which recharges the staff at
frame 50, then the lever bounce); pushing before the spin ends fast-forwards the rest. Sound
cues fire at BO2's notetrack frames 14, 29, 43 and the re-seat.

Each variant also gets its BO2 idle pose (`viewmodel_zomb_staff_idle` / `viewmodel_z_staff_upg_idle`)
as a rest pose on top of the bind pose: that is what flips the upgraded tip's knives outward and
extends its head studs. The head (the cuff above the cage, the tip and the crystal) is exported at 63.75% (`HEAD_SCALE`),
shrunk towards a gap in the mesh just below the cuff and tapered in so it meets the shaft cleanly;
the rest is BO2's size.

`tools/check_compile.sh` compile-checks all of this with Unity 5.6's own compiler, without
touching an open editor (it needs the game imported, i.e. `Assets/Managed/H3VRCode-CSharp.dll`).

To look at the rip without Unity, serve the repo root and open `tools/viewer.html`. The
`origins-staffs-viewer` launch config in the H3VR folder's `.claude/launch.json` does this on
port 8765.

## First-time Unity setup

1. Install Unity **5.6.7f1** and open `Unity/` directly, not through Unity Hub (Hub can hang
   on the splash screen with 5.6).
2. Run the extraction above so `Ripped/` is populated.
3. **Origins Staffs > First-Time Setup**. This runs MeatKit's **Import Game** (it finds H3VR
   through Steam), waits for the recompile, imports `tools/OtherloaderPackage-1.1.1.unitypackage`,
   and runs **Origins Staffs > Rebuild Ripped Prefabs**.

If the MeatKit menu is missing or there are compile errors about the game assembly, clear
**Player Settings > Other Settings > Scripting Define Symbols** and run **MeatKit > Scripts >
Import Game** again.

### MeatKit is pinned to 3.0.7: do not run "Check for updates"

MeatKit 3.1.x (the GitHub `main` branch as of 2026-10) crashes the editor on most script
reloads here: `System.ExecutionEngineException: SIGILL` in
`MeatKit.NativeHookManager.OnShutdownManaged`. Its 2026 "stability" rewrite detours a lot of
Unity's native code, and the shutdown detour fails on this machine (Windows 11, Meta Horizon
runtime installed). Disabling just its `TerminateMonoIOWorkers()` call did not help.

3.0.7 still uses the small 2023-era hook and survived repeated compile/reload cycles. Going
from 3.0.7 to 3.1.1 only changes `Assets/MeatKit/Editor` (3.1.x adds `PlayHelper.cs`,
`ManagedPluginDomainFix.cs` and `SafeAssemblyStripper.cs`) and `ProjectSettings/MeatKitVersion.txt`.
To move between versions, close Unity and copy the `Assets/MeatKit` folder from the release zip.

## Model notes

- BO2 units are inches. Ripped models import at `globalScale = 0.0254`, so 1 unit = 1 m.
- Every element shares one staff body (`t6_wpn_zmb_staff_world`, about 1.5 m). The element is
  only the tip and crystal on its tags.
- `t6_wpn_zmb_staff_view` is far more detailed but only covers the front half of the shaft,
  because that is all the player saw in BO2.
- `t6_wpn_zmb_staff_reload_<el>_world` sits at `tag_reload`, by the grip. It is the crystal
  housing BO2 swaps during its reload animation, and the planned H3VR magazine.
- Clip sizes (base/upgraded): fire 9/12, ice 6/9, lightning 12/18, wind 3/6. `upgraded2` and
  `upgraded3` are the charge-shot levels. Most damage is applied by GSC scripts, so the
  weapon files' damage values are not usable as-is.
- Effects (`fx` assets) cannot be exported by OAT and have to be rebuilt in Unity.

## Packaging

MeatKit writes bundles to `Unity/AssetBundles/<PackageName>/<Version>/`. **Build Staffs + Copy
Mod To r2modman** installs them into the r2modman Default profile for testing.

To publish, bump `version_number` in `manifest.json` and `versionNumber` in `thunderstore.toml`
(Thunderstore rejects a version twice), close Unity and H3VR, then:

```powershell
$env:THUNDERSTORE_TOKEN = "<service account token>"
./tools/publish.ps1
```

It refuses an unbumped or already-published version, builds headless
(`StaffAssemblyBuilder.BuildThunderstorePackage`: MeatKit zips the package into the folder above
instead of copying it to r2modman), checks the zip, and uploads it with `tcli publish`.
`./tools/publish.ps1 -BuildOnly` builds and checks the zip without publishing. Publishing has to
run on a machine with the BO2 rips, so it is a local step rather than a GitHub Action.

The build profile's README/CHANGELOG/icon fields point at `Assets/OriginsStaffs/Package/`.
`PackageDocsSync` copies the repo-root files there whenever the editor loads.

Gun sounds go through the staff's own `FVRFireArm` audio pools (`OriginsStaff.PlaySoundAt`):
`SM.PlayCoreSound` silently ignores the GunShot/GunMech/GunHand categories.

Every upgraded staff is an H3VR melee weapon (`MP` on the staff): each blade its upgraded idle
flips out of the tip (`ElementStyle.Blades` in the builder) gets a box collider fitted to its
vertices and a stab direction along the blade. H3VR's stab code takes a single `StabDirection`,
so `OriginsStaff.OnCollisionEnter` points it at whichever blade hit first.

Letting go of the rings while holding the lower half leaves the staff where it is in that hand
(grab-point interpolation off, no trigger) until a hand takes the rings again.

## Elements

All four staffs share one body, reload skeleton and pipeline; per element they differ in tip,
crystal, upgraded reload animation, sounds, glow colour and shot.

BO2 is the source of truth. Numbers come from the weapon files (`zone_dump/zm_tomb/weapons`) and
from the staff scripts in `zm_tomb_patch.ff` (`maps/mp/zombies/_zm_weap_staff_*.gsc`). OAT
dumps those as compiled bytecode; the decompiled text used here is
[plutoniummod/t6-scripts](https://github.com/plutoniummod/t6-scripts) (`ZM/Maps/Origins`).

**BO2 damage in H3VR.** BO2 works in zombie health: a staff hit kills a zombie whose health is
below the damage, or takes that much off. Sosigs have no health pool; one dies when its torso link
runs out of integrity (100, less 0.032 per point of blunt). `StaffDamage.Bo2ToBlunt` (1.6) makes
BO2's 2050 just enough to destroy a fresh standard torso, and `StaffDamage.WouldKill` is BO2's
health test. Kills drop the sosig like BO2's scripted deaths (no gore); other hits are blunt on
the torso.

| Element | BO2 behaviour, as ported |
| --- | --- |
| Fire | Fireball (1200 in/s), 100 in burst (upgraded 120 in). Base and upgraded alike throw three at once from the muzzle, 15 degrees apart, for one charge. BO2's `fire_spread_shots` staggers the side two by 0.2 s and starts them 50 in ahead aimed about 29 degrees out; play-tested, that sent them too far out, so it was reverted. Damage is tuned (play-tested), not ported. |
| Ice | Weapon: 2000 in/s for 0.3 s. Script (`_icicle_locate_target`, three searches per shot): the closest zombie within 600 in and 25 degrees, not already on ice, with a clear trace to a random body tag. Each is frozen and slowed with an icicle in its chest; 1.8-2.3 s later it shatters if 2050 (upgraded 3300) would kill it, else takes that and thaws. Shown as a spray of 7 icicles (BO2's ice projectile model), one aimed at each target. Play-tested: Ullr's Arrow throws 12 and freezes up to 5 (five searches). |
| Lightning | Weapon only (no script for the normal shot): 750 in/s ball, 2050 to the sosig hit plus 2050 falling to 1750 over 96 in (upgraded 3300, 3300 to 3000 over 128 in), behind cover blocked. Survivors are stunned (`zm_electric_stun`); every sosig hit gets sparks and BO2's zap. |
| Wind | Weapon: 1500 in/s, which the script deletes after 0.75 s. Script (`wind_damage_cone`): of the 12 zombies closest within 400 in, each within 45 degrees (upgraded 60) takes 2050 (upgraded 3300). No trace. Kills are launched away at 300 in/s with 5-35% lift; survivors are stunned. Hits land as the ball of wind passes each target. |

Beyond BO2, from play-testing: in BO2 the ice and wind projectiles never hurt anything
themselves, which in VR read as shots passing harmlessly through sosigs. Here a sosig an icicle
or the ball of wind actually touches is hit as if the script had picked it (ice still freezes at
most three per shot, and no shot hits a sosig twice). Ice shards also fly on for 2 s instead of
BO2's 0.3 s, because vanishing mid-air looked broken; BO2's 600 in still bounds the targeting.
Only Boreas' Fury keeps the wind cone: the base Staff of Wind hits only what its ball touches
(`StaffConeShot.UsesCone`), so the ball's hit radius matches its visible swirl (0.2 m).
The ball of wind blows away every sosig within 2 m of its path (`StaffBolt.NearRadius`), with
nothing solid in between: those BO2's damage kills are flung, the rest are knocked down and pushed
away as well as stunned. The charged shot's ball has no such area; it leaves its whirlwind.
Every ice and wind shot logs what it found (`[OriginsStaffs] IceShot_...: n sosig(s) within ...`).

### Charged shots (upgraded staffs)

BO2's upgraded staffs are fireType "Charge Shot": the shot goes on release, and holding the
trigger charges it to level 2 and 3, which fire the alt weapons `staff_<element>_upgraded2_zm` and
`upgraded3_zm`. The engine runs the charge, and neither the weapon files nor the scripts give its
timing or ammo cost, so here: level 2 at 1 s, level 3 at 2 s (`OriginsStaff.ChargeLevelTimes`), and
a charged shot spends one charge per level. Charging shows after 0.25 s with BO2's
`wpn_<element>staff_charge_1/2/3` cues and charge loop, a rising crystal glow and BO2's rumble
pattern (harder each level). Upgraded staffs are therefore no longer full-auto, as in BO2.

| Element | Charged shot, as ported (level 2 / level 3) |
| --- | --- |
| Fire | A grenade lobbed at 1300 in/s and 200 in/s up under 800 in/s^2, sticking to anything but sosigs, going off once it settles (at least 0.5 s). Plus 1 / 2 more 0.35 s apart, each 5 degrees lower and up to 15 to the side. Each burns for 5 s over 80 / 100 in, every 0.2 s hitting what is inside with 11500 / 20000: a kill bursts the body apart (half the time) or leaves it burning; survivors burn for 300 / 450 a second for 8 s. The last step doubles the radius. |
| Ice | A bolt at 2000 in/s for 0.3 s. Where it ends, 33 in up, a blizzard: after 1 s, for 6 / 9 s, every 0.1 s, every sosig within 175 in freezes and shatters 0.5-0.7 s later. One blizzard at a time. |
| Lightning | A ball from 100 in ahead, drifting 800 / 1200 in along the aim over 8 s (stopping at walls), then lingering 3 s. Every 0.5 s it reaches each sosig within 150 / 250 in that it can see (0.2 s apart), stunning it and dealing 2500 / 3500 a second until it dies or drifts out of range. One ball at a time. |
| Wind | A ball of wind at 1500 in/s that is not cut short (5 s). If it lands within 100 in of a sosig, that sosig is launched and everything within 250 in of it is launched or torn apart. Either way a whirlwind touches down there for 7 / 10.5 s, dragging sosigs within 250 in to its centre at 50 / 62.5 in/s, one every 0.5 s, and tearing them apart at 30 in. One whirlwind at a time. |

The ice storm and wind tornado loops exist only as FLAC, which Unity 5.6 cannot import;
`tools/flac.py` (a small numpy decoder) converts them during export.

Upgraded spawner icons: BO2 has no upgraded icon images. Its HUD marks an upgraded staff by
drawing a red glow (`zom_hud_craftable_staff_glow`) behind the icon (`STATE_GOT_UPGRADE` in
`questitemtombdisplay.lua`), so `export_assembly.py` draws the same red glow around each element
icon (`*_upgraded.png`).

Effects are rebuilt from BO2's effect textures (`FX_TEXTURES` in `export_assembly.py`), since
OAT cannot export `fx` assets. Static models for effects (the icicle) are exported to
`Ripped/Props`.
